# 定位与架构

本项目面向已有 Tripo Studio 登录会话、使用网页积分、需要保留参考及模型原件的生产任务。当前 Chrome 模式由 Agent 执行可见 UI 流程，扩展承担可重复的预算、记录和下载动作。平台服务负责计算，本仓库负责可恢复的操作及可检查的交付。

| 方案 | 公开来源支持的范围 | 与本项目的关系 |
|---|---|---|
| VAST-AI-Research / Tripo3D-Plugin-dsh | Skill 配合 tripo-cli，通过 Tripo API 完成生成、状态和下载，使用 API 凭据 | 已有 Agent + Tripo 工作流；与复用 Studio 网页会话是不同接入路径 |
| OpenCLI 的 Tripo Studio Smart Mesh adapter PR #2477 | 提案包含网页会话中的模型/纹理任务和状态查询，通过页面发起 Studio 请求；作者说明下载未包含 | 已有浏览器适配探索。该 PR 在本次核查时 closed 且未合并，作者测试声明未在本项目独立复现；不能推断其仓库当前全部能力 |

来源：[VAST 项目](https://github.com/VAST-AI-Research/Tripo3D-Plugin-dsh)、[OpenCLI PR #2477](https://github.com/jackwener/OpenCLI/pull/2477)。这里只比较所列来源，未做全面竞品覆盖。

本项目值得继续做的部分是：在用户指定的当前登录会话中，将实时报价、共享预算、一次提交、导出接续、文件检查和恢复证据连起来。浏览器扩展不是不可替代的技术壁垒；能持续维护页面变化、减少重复扣费和交付遗漏的可靠性才是实际价值。

## 现有组件的职责

| 组件 | 当前职责 | 不由它证明的事项 |
|---|---|---|
| JSON 任务与素材包 | 任务 ID、方案、额度、阶段、图像字节及哈希；由 policy.js / bundle.js 检查 | 人类授权、参考一致性和平台功能可用性 |
| Agent / Skill | 读取会话授权，实际看图，配置可见网页，检查实时价格、原任务、模型和文件，组织交付 | 安装 Skill 不自动提供浏览器、图像或 DCC 工具 |
| MV3 内容脚本 | 上传入口、设置快照、唯一公开按钮、点击前后页面比对 | 未经助手直接点击的所有操作不会被全面拦截 |
| MV3 Service Worker | 串行预算预留、未知提交阻断、持久记录、同标签页导出接续 | 不自动猜测提交成功，不自动重试付费或未知下载 |
| 文件诊断与资产项目 | 容器、哈希、材质依赖、骨骼与动作曲线；原件及视觉证据 | 文件结构正确不能替代美术、变形或游戏运行验收 |

任务格式见[任务契约](task-contract.md)，真实功能范围与操作顺序见[当前 Chrome 流程](current-chrome.md)。原有 Playwright CLI 是另一条队列入口，它目前止于 Studio 纹理结果，不应误称为扩展的完整生产调度器。

## 为什么需要记录再点击

付费阶段先在本地持久化 submitting 记录，再检查同一 URL、输入、按钮、设置、报价及余额，然后只点击一次。点击后记录 uncertain，读取原任务和扣费证据才关联 task/model ID。若浏览器连接丢失，保留记录并核查原任务；时间超时不会自动释放预算。

免费导出使用独立记录：先绑定模型、原标签页、文件名和设置，再点公开 Export。允许的 CDN 导航交给正常 Chrome downloads API；Studio 原生直接下载只被动关联唯一已有文件。接口接受后可以恢复原模型页，随后仍需检查 Chrome 状态及磁盘文件。

该机制避免观察连接中断后从头重跑，但还不是“精确一次”的平台事务保证。网页外操作、平台余额刷新延迟、未知保存费用和浏览器下载拒绝都需要保存证据并核对。

## 当前交付与后续重点

已取得带骨骼/实际变化曲线的四足 Walk、人形文本和多阶段动作 GLB，并完成静态高低模与 FBX/OBJ 原生包下载。详细设置、贴图编辑及平台限制有单独验收条目。

当前缺口包括部分新功能的真实提交/导出、最终设置快照补丁的浏览器验收、多视图一致性与重建形体的完整验收、绑定变形/根运动/游戏导入，以及最终美术判断。新增公开阶段可以登记报价和防重，但这不代表该功能已经可用。

后续应先补这些证据、完善可恢复操作，再考虑批量调度和更多 Agent 的适配。人形与四足保持独立验收；新页面版本或地区下载地址先观察并做最小适配。使用正常登录和浏览器权限，遇到验证码或工具安全停止保留现场，按允许的恢复路径处理。
