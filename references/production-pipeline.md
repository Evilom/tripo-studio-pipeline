# Studio 生产、恢复与交付管线

当前推荐入口是用户指定的已登录 Chrome、版本化任务和 MV3 助手。Agent 操作可见网页，扩展保存提交意图并接续下载，文件脚本检查及打包。原有 CLI 队列是另一入口，当前仅自动运行到 Studio 纹理结果。

~~~mermaid

    A["任务、参考、已有模型与授权"] --> B["原页核对 URL / 设置 / 实时报价"]
    B --> C["保存意图 → 公开按钮一次"]
    C --> D["关联原模型 / 接受证据 / 实际扣费"]
    D --> E["低模与 UV / 贴图 / 按需绑定动作"]
    E --> F["原高模及原生包留在本地"]

    G --> H["文件、材质、真实视窗检查"]
    H --> I["显式低模计划 → 精简包 / 哈希"]
    I --> J["Drive 上传 → 元数据核对"]
    J --> K["授权通知接收方 → 领取哈希回执"]
~~~

## 1. 接手与付费

先核对当前参考、原记录和磁盘原件。用户已经点击高模生成时，从原模型继续；提交后显示的 Generate 价格不能冒充历史实际费用。余额上涨时保留支出高水位，不能重置原共享额度。任务格式见[任务契约](task-contract.md)。

每次付费先保存候选、阶段、实际 URL、输入哈希、设置和报价，再点击一次。未确认接受的 submitting / uncertain 阻断后续付费；资产列表、处理状态、编号与扣费在原任务核查，不依靠观察超时决定重跑。

模型 ID、平台任务 ID、转换产物 UUID和Chrome下载编号各有含义。字段使用真实来源，拿不到平台任务 ID时明确留空。完成状态至少分为页面完成、文件通过、视觉检查及游戏验收。

游戏用途通常先做所需低模和2K纹理，保存原高模。按用户具体规格选面数与分辨率；先完成几何/UV再贴图，骨骼和动画按交接分工决定。保存/应用可能扣费，未显示价格不证明免费。

## 2. 导出与连接恢复

打开原生 Export / 导出面板，明确文件名、格式、分辨率、骨骼和动作。日常使用网页助手的“自动导出并保存一次”：意图先落盘，设置未变才点唯一公开 Export。

CDN导航用已批准的正常Chrome下载接口接续；Studio直接下载则被动关联唯一已有文件。结果不明时查自己的下载记录、实际文件与partial状态，不能连续点导出。未知来源、歧义或Chrome拒绝保留错误；不关闭保护，不通过私有请求绕过控制工具的安全停止。

浏览器控制超时与Tripo提交失败分开处理。优先保留原模型和文件，按所用工具的文档恢复同一浏览器连接；扩展重载后连接编号可能改变，以最新清单和同一实例身份确认，不反复使用失效编号。连接扩展、工作流助手和Tripo页分别记录版本与状态。

一次原生下载已保存但控制观察超时时，核对文件后继续，不重新导出或重新生成。使用助手路径时，以其持久下载编号及磁盘文件作为接续依据；不要同时启动第二个会话或另一下载等待器。不能从某一次等待器超时推导所有下载API不可用。

0.6.0新增 /zh/workspace 路径与中英文导出文本适配，固定阶段身份不随语言改变，控件定位仍按语言与路由区分。其他公开阶段还以操作名称区分，翻译或改名不构成重新提交授权；沿用原记录并核对实际阶段。此次为离线适配，中文真实重载验收尚待完成；未知导出开关不会默认为关闭。已实测0.5.1的英文下载链路和本次0.6.0源码验证分开记账。

## 3. 文件与视觉检查

~~~powershell
python scripts/verify_glb_motion.py '完整路径/model-low.glb'
python scripts/verify_glb_motion.py '完整路径/model-walk.glb' --require-animation
~~~

确认GLB容器、嵌入材质、真实贴图尺寸与模型映射；原生ZIP检查CRC，OBJ检查MTL/贴图引用，FBX保留同名.fbm目录并做DCC导入检查。诊断的适用范围见[当前Chrome验收矩阵](current-chrome.md)，不能替代完整glTF、DCC或游戏验收。

网页Quad标签不等于全部面都是四边形。分别记录原生面型分布、原生顶点、GLB三角数与导出顶点。正侧背预览应来自同一实际模型的相机旋转；“近正面/背面斜角”如实命名，不把截图冒充独立正交参考。

## 4. 精简交付与云端接收

本地保留原高模、原下载包和操作账本。给后续开发者默认交付低模：自包含GLB、按需原生FBX及全部材质、必要参考和少量预览。GLB已含贴图时不再塞一份外置副本；已展开FBX时不再附相同ZIP；OBJ只在消费者确实需要时追加。

用[低模打包说明](low-delivery.md)和显式计划生成包。计划选择文件，脚本限制实际三角数、贴图尺寸和最终字节数，检查边界、CRC与SHA256；不会重采样模型、图片或自动上传。

Drive等外部交付使用已授权的连接器。上传完成后读回名称、类型和字节数；可取得校验值时与本地比较。包中剔除账户余额、连接标识、签名地址和私有操作日志。保留原分享范围；没有具体授权时不改为公开链接。

用户授权通知接收方后发送已验证的链接、文件名、字节数、SHA256和待接手范围。发送成功与对方领取成功分开记录；对方回报实际文件哈希和CRC后才标记领取确认。云端无法回复本地会话时，保存其他可信回执，不重复上传或要求对方索取高模。

## 已跑过的实例与优化顺序

2026-10-04/05：续接用户已生成高模，一次40积分重拓扑后得到原生4,941面（4,333四边面＋608三角面）、GLB9,274三角及三张2K贴图。三格式正常助手下载完成并返回原模型。完整本地包57.3MB；按消费者需求去高模、去重复后为9.7MB，减少83%。Drive大小读回匹配，接收方独立确认SHA256、CRC与15个文件。这里只公布脱敏数据。

本次落实：中文路径/导出适配、带预算及哈希的低模打包入口、一次提交观察的CI测试时序。后续优先补齐0.6.0中文真实页面验收、未测新功能、DCC/引擎导入与变形检查，再评估根运动、纹理压缩或更多下载地区。新增域名、自动重试和无人值守批量调度均需新的实际证据与明确范围。
