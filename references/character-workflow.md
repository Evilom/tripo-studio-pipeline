# 人物双资产工作流

用于人物参考到本地模型交付；断点恢复另见 [recovery.md](recovery.md)，文件记录见 [delivery.md](delivery.md)。以用户和项目最新规格为准，本流程不固定角色名单、轮次或历史项目 ID。

## 身份与来源

为每人先确定角色、扮演者、作品、版本/时期、标志服装和排除项。群体条目先核实成员；声音梗或无可核实实体的条目记录实际原因，不虚构可建模人物。

参考证据足以确定本人脸部和同套服装后开始生产，不为补齐全部摄影角度无休止搜索。视频优先 B 站原片/名场面；通用搜索反复给搜索页时，直接检查公开 B 站搜索界面的可见标题和 BV 链接。可靠原剧照片可补角度。

保存源视频链接、BV、分 P、实际取帧秒数、实际画面文件；多人镜头写明目标人物位置。核验播放时长，不超过公开可播放范围。不把 AI 换脸、重绘、其他剧版、其他演员、晚年重扮、游戏或手办照片当作本人原片脸部证据。

`assets/<actor_slug>/references/sources.json` 的最小信息示例：

```json
{
  "character": "示例角色",
  "performer": "已核实扮演者",
  "work": "原作名称与版本",
  "look": "同一时期的标志服装",
  "sources": [{
    "url": "实际原片链接",
    "bvid": "实际 BV 号",
    "part": 1,
    "seconds": 12.4,
    "frame": "assets/example_actor/references/frame-001.png",
    "subject_location": "画面右侧",
    "observed": "脸部、帽子和上衣",
    "actually_viewed": false
  }],
  "inferred": ["背部未出镜的服装细节"],
  "excluded": ["另一演员或另一版本"]
}
```

示例不是已核实证据；字段按真实观察填写。若 `readyState=4`、seek 秒数正确却得到空白帧，将该视频页置前台，在允许播放范围内 seek 后静音播放约 0.4 秒，再暂停截图。仍要实际看图核对是否空白、重复或错人，记录真实时间；播放状态不能替代画面证据。

## 一轮六张图

先查看原参考再生成图。使用环境中实际可用的图像生成/编辑工具；没有此能力时保留参考与提示词并报告缺少的能力，不把复制原片称作生成完成。生成后立即保存原件及工作副本；超时先续等原句柄、查已产出图，不因观察中断重发同一请求。

1. 原片生成一次**头部正面**：独立完整头颈、中立闭嘴、均匀光线、灰底、近正交，保留脸型、五官比例、发型/胡须/面妆/头饰。
2. 由同一正面头图生成**头部左侧、背面**，保持比例、发型、帽子和光照。未拍到的后脑或帽背注明推断。
3. 同一头像＋服装原片生成**全身正面大字 A-Pose**，保证同一演员、同一服装、头身比例和鞋袜；不手持遮挡肢体的道具。
4. 由该全身图生成**全身左侧、背面**，旋转相机而非重新摆姿势。不能裁掉帽顶、手指或鞋底。

可改写的全身约束提示：

> 保持参考人物身份、脸型与同一套服装。中立站立，躯干正直，双臂向两侧约 45 度，肘近伸直，腕中立，手掌与衣服分离，手指自然分开。双腿适度分开、双脚平行落地。全身完整入镜，均匀照明；侧背只旋转视点，姿势与比例保持一致。

逐张实际查看六图，排除身份、服装或姿态漂移。约 35° 开臂、略偏三分之四的侧图、指间不足等如实记录，不能因此虚报可绑定；明显错图先修输入。本轮已接受任务的问题保留待处理，除非用户另行授权返工，不重发付费模型。

## 输入与免费预览

```text
staging/<actor_slug>_head_v1/{front,left,back}.png
staging/<actor_slug>_body_apose_v1/{front,left,back}.png
inputs/<head_asset_id>/{front,left,back}.png
inputs/<body_asset_id>/{front,left,back}.png
```

`inputs` 保存审核后的副本，保留 staging 与图像工具原件。记录 asset ID、输出 stem、character ID 与 roster 条目的显式对应；不要只在上一角色脚本或清单中替换几处文字。

多视图的每个实际槽位逐一完成“选文件 → 加载结束 → 图片 complete 且 naturalWidth 有效 → 已加载数增加”，再操作下槽。进入实际多视图面板并按方向标签定位，不假设旧版单图缓存会迁移，不用变化中的 input 下标猜方向。实际看 front/left/back 三个缩略图、右槽空白、HD 模式与唯一页面；读图片真实尺寸及签名，不假定输出总是 1024×1536。

预览与提交分两次工具调用，留出实际看图的步骤。提交前再次比对签名、角色、槽位和选中页面；只比对三张同尺寸图片不足以证明人物或方向正确。

## 两条资产轨道

| 阶段 | 头部 | 全身 | 下一阶段证据 |
|---|---|---|---|
| 首次 HD | 独立高清头颈 | 同服装大字 A-Pose | 接受 ID/URL 和 checkpoint 已落盘 |
| 收取原 HD | 保留未减面源 | 保留未减面源 | 本地 GLB 完整，正侧背与脸部已实际查看 |
| 首次拓扑 | 普通 Quad，目标 30,000 | 普通 Quad，目标 10,000 | Smart Low Poly 明确关闭，面数输入和滑块一致 |
| 首次纹理 | 颜色目标 4K | 颜色目标 4K | 等待原纹理完成，记录实际结果 |
| 导出 | 纹理 GLB＋原生 OBJ 包 | 纹理 GLB＋原生 OBJ 包 | 文件落盘、OBJ/MTL/贴图可用 |
| 检查 | 对照 HD 的脸部细节 | 姿态、服装、肢体间隙 | 原生面型诊断、实际图像观察与缺陷记录 |

这些参数用于首次任务，不为参数统一而重做已接受的旧任务。先切换 Quad 与 Smart Low Poly 开关、等待控件范围更新，再填目标数，触发 change/blur，确认输入值与滑块 `aria-valuenow` 都等于目标。模式状态应由 `aria-pressed`/`data-state`/`aria-checked` 等实际属性确认；仅填写文本可能未提交到滑块，或稍后被旧上限夹回 10,000。

GLB 通常三角化，不能用其三角面数证明原生四边面。拓扑减少五官细节时保留 HD 并列出差异；不从全身低模裁头，不反复局部打磨或焊接替代人物还原度。

## 完成一人后推进

按 [交付记录](delivery.md) 检查原 HD、纹理模型、原生包、诊断和图像证据。宽袍下面的腿部结构须实际核实；头身各自归一化时记录方向/比例与待 Wrap 对齐情况。模型候选不是已完成骨骼和动画变形验收。

小瑕疵留档供后续 Wrap；明显错人、破面或不可用文件单列待处理，不混入最终通过。同步角色交付入口、roster 与 PROGRESS，立即推进下一位。已有平台任务计算期间可准备下一位参考或本地渲染，同浏览器 UI 仍只有一个操作者。
